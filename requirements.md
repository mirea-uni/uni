# Функциональные требования

> **UNI** · Платформа для совместного владения имуществом  
> **Объём:** первая версия продукта · **Срок проекта:** 15 декабря 2026 года

## 1. Назначение

Платформа позволяет совладельцам учитывать общее имущество, видеть доли владения и бронировать его использование на определённые даты. Доступное количество дней рассчитывается пропорционально доле участника в каждом календарном месяце.

Правила использования задаются простым шаблоном **Agreement as Code**: приложение хранит параметры и версии договорённостей и применяет их при проверке бронирований.

## 2. Участники и доступ

| Участник | Возможности |
|---|---|
| Пользователь | Регистрация, вход, просмотр имущества, в котором он участвует |
| Совладелец объекта | Просмотр долей, правил, календаря и доступного лимита; бронирование и инициирование выхода |
| Участник с правом управления | Управление карточкой, составом участников, долями и правилами в пределах согласованных полномочий |

Конкретный порядок выдачи прав управления и согласования изменений определяется до реализации соответствующих операций. Статус создателя объекта сам по себе не означает юридических полномочий.

## 3. Требования к функциям

Исполнители, оценки, зависимости и спринты ведутся в [YouTrack](https://aeim-project.youtrack.cloud/issues?q=project%3A%20UNI).

### 3.1. Регистрация и вход

| Требование |
|---|
| Пользователь может зарегистрироваться с email и паролем и войти в приложение. Повторная регистрация с тем же email отклоняется. |
| Приложение поддерживает завершение сессии и ограниченный срок действия авторизации. |
| Сервер проверяет авторизацию и права на объект при каждом защищённом действии. Пользователь вне объекта не получает его закрытые данные. |

### 3.2. Имущество и доли

| Требование |
|---|
| Участник с правом управления может создать и изменить карточку имущества: название, описание, тип и фотографию. |
| Пользователь видит список своего имущества и свою долю в каждом объекте; список поддерживает пагинацию. |
| В карточке объекта отображаются сведения об имуществе, участники и их процентные доли. |
| Приложение позволяет добавлять участников и изменять доли по согласованным правам. Сервер проверяет ограничения долей и не допускает повторного участия одного пользователя в одном объекте. |
| Удаление или архивирование имущества доступно по согласованным правилам. Операция не должна приводить к утрате необходимой истории действий. |

### 3.3. Правила использования — Agreement as Code

| Требование |
|---|
| Для объекта применяется простой шаблон правил с параметрами. Редактор произвольных правил в первую версию не входит. |
| Количество доступных дней определяется долей владения отдельно для каждого календарного месяца. |
| Участник видит действующую версию правил, свой месячный лимит, использованные и оставшиеся дни. |
| Приложение сохраняет предыдущие версии правил и сведения об их принятии; изменение правил выполняется по согласованному процессу. |
| Проверка бронирования выполняется сервером по применимой версии правил. Результат проверки и причина отказа доступны пользователю. |

**Основа расчёта:**

`Базовая доля дней = число календарных дней месяца × доля владения / 100`

Например, при доле 50% в месяце из 30 дней базовый лимит составляет 15 дней. Для дробного результата требуется отдельное согласованное правило округления и распределения остатка.

### 3.4. Бронирование

| Требование |
|---|
| Совладелец может просмотреть календарь занятых периодов объекта и создать бронирование на выбранные даты. |
| Перед подтверждением сервер проверяет права участника, применимые правила, доступный лимит и пересечения с действующими бронированиями. |
| Подтверждённые бронирования одного объекта не пересекаются. Конкурентные запросы не должны создавать двойную бронь или превышать лимит. |
| Период, затрагивающий несколько месяцев, проверяется по лимиту каждого из этих месяцев. |
| Участник может изменить или отменить бронирование в рамках согласованных полномочий и переходов состояния. |
| Изменение дат выполняется атомарно: при отказе исходная бронь и учёт дней сохраняются. Возврат дней при отмене определяется согласованными правилами. |
| После создания, изменения или отмены бронирования календарь и остаток дней отображают актуальные данные. |

### 3.5. Выход из совместного владения

| Требование |
|---|
| Участник может инициировать выход из совместного владения и видеть статус своего запроса. |
| Если процесс требует согласования, действия доступны соответствующим участникам согласно их правам. |
| Завершение выхода изменяет доли, доступ и будущие бронирования по согласованному сценарию; исторические записи сохраняются. |

### 3.6. История и предоставление данных

| Требование |
|---|
| Приложение фиксирует значимые действия с имуществом, участниками, долями, версиями правил, бронированиями и запросами на выход. |
| Событие содержит автора, время, объект, действие и согласованные детали: прежние и новые значения, применимую версию правил и результат проверки, где это относится к событию. |
| Пользователь может просмотреть доступную ему историю объекта и выгрузить согласованный набор данных. |
| Обычные пользовательские операции не позволяют изменять или удалять прошлые события аудита. Выгрузка не содержит чужих закрытых данных, паролей и токенов. |
| История владения и действий сохраняется после выхода участника; доступ к ней определяется отдельно согласованными правилами. |

## 4. Границы продукта

Приложение не проводит законодательных проверок и не определяет юридическую действительность прав, долей или договорённостей. Оно хранит и предоставляет данные, которыми участники могут воспользоваться при разбирательстве, включая судебное.

В первую версию не входят:

- юридическое оформление владения и разрешение споров;
- платежи, расчёты стоимости долей и интеграция с API ЦБ;
- торги, праздничные очереди и другие сложные механизмы распределения дат;
- произвольный конструктор правил;
- Telegram-бот — отдельное направление с низким приоритетом.

## 5. Решения, требующие согласования

Эти вопросы не считаются решёнными настоящим документом. До реализации соответствующей функции команда фиксирует выбранное поведение и примеры проверки.

| Область | Открытые вопросы |
|---|---|
| Права | Кто добавляет участников, меняет доли и правила; как выдаются полномочия; как принимаются изменения |
| Доли | Точность процентов, допустимая сумма, незаполненная доля, изменение доли внутри месяца |
| Месячный лимит | Округление, распределение остатка, перенос неиспользованных дней |
| Даты | Включённость начальной и конечной дат, часовой пояс, минимальный период, бронирование прошедших дат |
| Бронирование | Момент подтверждения, состояния, сроки и условия изменения/отмены, возврат лимита |
| Версии правил | Момент вступления в силу и влияние на уже созданные бронирования |
| Выход | Необходимые согласования, перераспределение долей, судьба будущих броней и последующий доступ |
| Удаление имущества | Условия удаления или архивирования и сохранения связанных данных |
| История | Полный состав событий и выгрузки, сроки хранения и права доступа |
| Фотографии | Допустимые форматы, размер и условия доступа |
